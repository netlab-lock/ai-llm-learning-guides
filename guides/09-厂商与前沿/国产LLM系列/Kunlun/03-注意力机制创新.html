Kunlun

天工大模型的注意力设计特色与优化

概述

天工大模型（Kunlun/Skywork）在注意力机制上的核心创新体现在两个方向：(1) 搜索增强注意力（Search-Augmented Attention）——将搜索引擎的检索能力直接集成到注意力计算中，使模型在生成每个token时能动态参考外部知识；(2) 层级化注意力温度（Hierarchical Attention Temperature）——浅层聚焦局部语法、深层捕获全局语义，实现不同深度的差异化注意力模式。这两项创新使天工3.0在事实性问答和知识密集型任务上的准确率提升约15%。

搜索增强注意力与层级化温度机制

天工3.0在注意力机制上的核心创新体现在"搜索增强注意力"（Search-Augmented Attention）的设计上。昆仑万维将搜索引擎的检索能力深度集成到注意力计算中——当模型处理长文本或复杂问题时，首先通过内置的检索模块从知识库中获取相关文档片段，然后将这些检索结果作为额外的Key-Value对注入注意力层，使得模型能够在生成过程中动态参考外部知识。配合"层级化注意力温度"机制，浅层使用较低温度聚焦局部语法信息，深层使用较高温度捕获全局语义关联，使模型在不同深度自动学习不同粒度的语义特征。

搜索增强注意力: Attn(Q, [K; K_retrieved], [V; V_retrieved])
层级化温度: τ(l) = τ_base × (1 + α × l / L)
其中 l 为当前层数, L 为总层数, α 为温度增长系数(天工取α=0.5)
浅层(l=0): τ=τ_base (低温, 注意力集中)
深层(l=L): τ=τ_base×1.5 (高温, 注意力平滑)

说明：标准Attention(Q,K,V)仅使用输入序列内部的Q-K-V计算。搜索增强注意力将检索结果K_retrieved、V_retrieved拼接在原K、V之后，使模型能同时关注输入上下文和外部知识。层级化温度让浅层（靠近输入）的注意力更尖锐（关注局部语法），深层（靠近输出）的注意力更平滑（捕获全局语义）。

搜索增强注意力 — 完整数学形式化

🔬 搜索增强注意力 — 完整数学形式化

1. 搜索KV与本地KV的融合公式
设本地上下文长度为n，检索结果长度为m，则融合后的注意力计算为：

Attention(Q, K, V) = softmax( [QK_local^T; QK_search^T] / √d ) [V_local; V_search]
其中:
Q ∈ R^{n×d} (查询来自本地序列)
K_local ∈ R^{n×d} (本地Key)
K_search ∈ R^{m×d} (检索Key, 来自搜索引擎)
V_local ∈ R^{n×d_v} (本地Value)
V_search ∈ R^{m×d_v}(检索Value)
[;] 表示沿序列维度拼接, 总KV长度 = n + m
注意力矩阵大小: n × (n+m), 而非标准注意力的 n × n

具体数值示例：当天工处理一个n=4096的输入查询，检索返回m=2048的外部知识时，注意力矩阵从4096×4096=16.8M元素扩大到4096×6144=25.2M元素（+50%）。FlashAttention的分块策略使这个额外开销在IO层面几乎免费。

2. 注意力温度公式：T(layer, position) = f(layer_depth, distance_to_query)

T(l, i) = τ_base × (1 + α × l/L) × (1 + β × i/n)
其中:
l = 当前层数 (0, 1, ..., L-1), L=80 (天工70B)
i = KV token相对于query的位置距离
n = 序列长度
τ_base = 1.0 (基础温度)
α = 0.5 (深度温度系数)
β = 0.2 (距离衰减系数)

浅层(l=0): T = 1.0 × 1.0 × (1+0.2i/n) ≈ 1.0~1.2 (低温, 尖锐注意力)
深层(l=79): T = 1.0 × 1.49 × (1+0.2i/n) ≈ 1.49~1.79 (高温, 平滑注意力)

设计动机：温度T在softmax中作为分母：softmax(QK^T / (√d × T))。T越大，注意力分布越平坦（更多token获得显著权重），深层因此能捕获更广泛的全局语义关联。

检索机制细节：天工使用混合检索——BM25（稀疏，精确匹配关键词）+ DPR（Dense Passage Retrieval，稠密向量相似度），分数加权融合：score = 0.3 × BM25 + 0.7 × cosine(q, d)。检索延迟约150-300ms，通过异步Prefill流水线隐藏。
💡 Kunlun特有经验：搜索增强注意力的检索结果质量直接决定性能。天工团队发现，检索文档的chunk大小以256-512 token为宜（太短缺乏上下文、太长引入噪声），检索top-K取5-8篇时效果最佳。在MMLU知识问答上，检索增强使准确率从72.3%提升到84.1%（+11.8%）。
⚠️ Kunlun特有陷阱：搜索增强注意力会使每个请求的Prefix Cache失效（因为检索结果随查询变化，导致KV Cache的prefix不同）。天工的解决方案是建立检索结果缓存层——相同查询在TTL=1小时内复用检索KV，将Prefix Cache命中率从<10%恢复到约45%。

层级化注意力温度 — 完整推导与量化分析

🔬 层级化注意力温度 — 完整推导与量化分析

1. 为什么需要层级化温度？
Transformer不同层天然学习到不同粒度的特征：
• 浅层（l < 20）：主要捕获局部语法（词性标注、短语结构、局部共现），需要尖锐的注意力分布聚焦于邻近token
• 中层（20 ≤ l < 50）：捕获句法关系（主谓宾、依存关系），需要中等宽度的注意力
• 深层（l ≥ 50）：捕获全局语义（篇章结构、主题一致性、长距离指代），需要更宽的注意力分布

数学直觉：标准softmax对所有层使用相同温度τ=1。但实验表明，浅层的最优注意力窗口约±50 tokens，深层约±500 tokens。层级化温度通过调节softmax的锐度来匹配这一需求：

P(attend to token j | query i at layer l) = exp(q_i^T k_j / (√d × T(l))) / Σ_z exp(q_i^T k_z / (√d × T(l)))

当T(l)较小(浅层): 分布更尖锐 → 只有最近的/最相关的token获得高概率
当T(l)较大(深层): 分布更平坦 → 更多token获得显著概率 → 全局感知


2. 温度参数的学习方法

方案A：预定义（天工采用）
T(l) = τ_base × (1 + α × l/L)，α=0.5
优点：零额外参数、训练稳定、可解释性强
缺点：对所有任务使用相同温度曲线

方案B：可学习（实验对比）
T(l) = softplus(γ_l)，γ_l为可学习参数
优点：每层自动学习最优温度
缺点：增加80个参数（可忽略），但训练初期不稳定（温度可能发散到很大/很小）

# 方案B的PyTorch实现 class LearnableTemperature(nn.Module): def __init__(self, num_layers): super().__init__() self.temp_params = nn.Parameter(torch.zeros(num_layers)) # 初始化为0 → softplus(0)=0.693 def forward(self, layer_idx): return 1.0 + F.softplus(self.temp_params[layer_idx]) # 范围[1.0, +∞)

实验结果：可学习温度在perplexity上仅比预定义优0.02（3.40 vs 3.42），但训练时间增加5%（因梯度不稳定需要更小学习率）。天工最终选择预定义方案。

基础注意力机制

为什么天工选择GQA而非MHA/MQA？在推理部署中，KV Cache的显存占用直接决定了单GPU能支持的并发数。天工的70B模型如果采用标准MHA（64个KV Head），每个128K请求的KV Cache约33GB；采用GQA（8组共享，8个KV Head）后降至约4.25GB——8倍压缩使得单A100可支持8个并发请求（vs MHA的1个），吞吐量提升8倍。

KV Cache 显存 = 2 × n_layers × n_kv_heads × d_head × seq_len × bytes
MHA (64 KV heads): 2 × 80 × 64 × 128 × 128K × 2 = ~33.5 GB
GQA (8 KV heads): 2 × 80 × 8 × 128 × 128K × 2 = ~4.2 GB
压缩比: 64/8 = 8×
质量损失: <1% (perplexity从3.40→3.43)

说明：GQA将64个Query Head分为8组（每组8个），共享1个KV Head。天工的实验表明：GQA在perplexity（语言建模质量指标）上的损失<1%，但KV Cache显存节省8倍。这在长上下文推理场景下尤为重要——128K上下文的MHA方案在单A100上甚至无法运行。

💡 天工GQA配置：天工70B模型采用n_heads=64（Query）, n_kv_heads=8（KV），即8个Query Head共享1个KV Head。这是LLaMA-3和Mistral的相同选择，已被验证为质量-效率的最优平衡点。
⚠️ GQA部署陷阱：GQA的KV Cache布局与MHA不同，推理引擎需要专门适配。vLLM从v0.4.0开始原生支持GQA，但早期版本需要将GQA转换为MHA格式（浪费显存）。TensorRT-LLM的GQA支持也需要正确配置num_kv_heads参数，否则会回退到MHA模式导致OOM。

Multi-Head Attention 基线

天工采用 Multi-Head Attention（MHA）作为基础注意力框架，但在多个维度上进行了针对性改进。标准 MHA 的计算复杂度为 O(n²d)，在长序列场景下成为瓶颈。

注意力公式：Attention(Q, K, V) = softmax(QK^T / √d_k)V。天工在此基础上引入了多种变体和优化技巧，降低计算成本的同时保持或提升模型质量。

GQA（Grouped Query Attention）

天工采用了 GQA 机制，在标准 MHA 和 MQA 之间取得平衡。多个 Query Head 共享一组 Key-Value Head，减少 KV Cache 的显存占用，同时保持比 MQA 更好的模型质量。

MHA（多头注意力）

每个 Head 独立的 Q/K/V，质量最高但 KV Cache 最大。传统基线方案。

MQA（多查询注意力）

所有 Head 共享同一组 K/V，KV Cache 最小但质量有损。极致效率方案。

GQA ✅ 天工选择

分组共享 K/V，兼顾质量与效率。4-8 个 Head 共享一组 K/V，平衡点最优。

位置编码优化

为什么天工选择RoPE而非ALiBi或学习式位置编码？RoPE（Rotary Position Embedding）的核心优势是支持长度外推——训练时用4K上下文训练的模型，通过NTK-aware插值可外推到128K甚至更长，无需重新训练。这对天工智能体的长文档处理场景至关重要（如分析50页PDF合同、处理10万字小说摘要）。

RoPE旋转矩阵: R(θ, m) = diag([cos(mθ₁), -sin(mθ₁), cos(mθ₂), -sin(mθ₂), ...])
注意力得分: qₘᵀkₙ = (Rₘq)ᵀ(Rₙk) = qᵀR_{n-m}k (只依赖相对距离m-n)
NTK-aware缩放: θ'_i = θ_i × (L_target / L_train)^{d/(d-2)}
天工配置: 训练长度4K → 推理长度128K, 缩放因子=32
🔬 NTK-aware RoPE缩放 — 频率混合数学推导

1. 为什么需要频率混合（Frequency Mixing）
RoPE的每个维度对应一个不同频率：θ_i = base^{-2i/d}，其中base=10000。
• 高频维度（i小）：θ_i大，旋转快 → 编码局部位置（相邻token区分度高）
• 低频维度（i大）：θ_i小，旋转慢 → 编码全局位置（远距离token也能区分）

直接线性插值（Linear Interpolation，即位置m → m/s）的问题：
• 高频维度被过度压缩 → 相邻token无法区分（"位置混叠"）
• 低频维度未被充分利用 → 仍有大量编码空间浪费

2. NTK-aware的频率混合公式推导
核心思想：不同频率分量应该使用不同的缩放因子。高频少缩放（保持局部精度），低频多缩放（利用编码空间）。

原始频率: θ_i = base^{-2i/d}, i = 0, 1, ..., d/2-1

NTK-aware缩放后: θ'_i = θ_i × s_i

其中缩放因子 s_i 随频率变化:
s_i = (L_target / L_train)^{1 - 2i/d}

等价形式（更直观）:
θ'_i = (base × s^{d/(d-2)})^{-2i/d}
其中 s = L_target / L_train (长度扩展比)

具体推导:
令新base' = base × s^{d/(d-2)}
则 θ'_i = (base')^{-2i/d} = base^{-2i/d} × s^{-2i/d} = θ_i × s^{-2i/d}

但NTK-aware实际使用:
θ'_i = θ_i × [ (1-λ_i) × 1 + λ_i × (1/s) ] ← 高频×1, 低频×(1/s)
其中 λ_i = 2i/d (频率权重, 0→高频, 1→低频)

关键观察：线性插值对所有维度统一除以32，导致最高频维度θ从1.0降到0.031（相邻token几乎无旋转差异）。NTK-aware保持高频维度不变（θ=1.0），只压缩低频维度，从而保留了局部位置精度。

4. YaRN：NTK-aware + 温度缩放的完整公式
天工实际使用的是YaRN方法，在NTK-aware基础上还引入了注意力温度缩放：

YaRN = NTK-aware RoPE + Attention Temperature Scaling

RoPE部分: θ'_i = θ_i × [γ(i) + (1-γ(i)) × 1/s]
其中 γ(i) = 2i/(d-2), s = L_target/L_train

注意力温度: τ' = τ × √s = 1.0 × √32 ≈ 5.66
(补偿因长度增加导致的注意力分数方差减小)

完整注意力计算:
Attn = softmax( QK^T / (√d × τ') ) V

天工实测效果:
4K训练 → 128K推理, "大海捞针"准确率: 45% → 82%
perplexity: 3.40(4K) → 3.52(128K), 退化仅3.5%


5. 频率混合的几何直觉 

频率混合 vs 线性插值 — 极坐标视角

线性插值 (位置m → m/32):
  所有频率统一压缩 → 高频维度"折叠" → 位置混叠
  θ'_i = θ_i / 32  (所有维度相同缩放)

NTK-aware (频率混合):
  高频维度: 几乎不缩放 → 保持局部精度
  低频维度: 大幅缩放 → 扩展全局范围
  
  极坐标图 (一个2D子空间):
  
  线性插值:              NTK-aware:
  ┌──────────┐           ┌──────────┐
  │  ···     │ 密集折叠   │  · · ·   │ 均匀分布
  │ ·····    │ (混叠)    │ ·   ·    │ (无混叠)
  │·······   │           │·     ·   │
  │ ·····    │           │ ·   ·    │
  │  ···     │           │  · · ·   │
  └──────────┘           └──────────┘
  角度范围: [0,π/32]      角度范围: [0,π] (高频)
  + [0,π/16]             + [0,π/32] (中频)
  + ...                  + [0,π/128] (低频)

说明：RoPE将位置信息编码为旋转变换，使得两个token的注意力得分只与它们的相对距离有关（与绝对位置无关）。NTK-aware插值通过调整不同频率分量的旋转速度来扩展上下文：高频分量（捕捉局部关系）缩放较少，低频分量（捕捉全局关系）缩放较多。天工通过YaRN（NTK-aware + 温度缩放）将RoPE从4K扩展到128K，在"大海捞针"测试上的准确率从45%提升到82%。

RoPE（旋转位置编码）

天工采用 RoPE（Rotary Position Embedding）作为位置编码方案。RoPE 通过旋转矩阵将位置信息编码到 Query 和 Key 向量中，天然支持相对位置感知。

  • 相对位置感知 — RoPE 编码的是相对距离而非绝对位置，泛化性更好
  • 无需学习参数 — 位置编码是确定性的旋转变换，不引入额外参数
  • 外推性好 — 结合 NTK-aware 缩放等技术，可外推到训练时未见过的长度
  • 与注意力兼容 — 与 Flash Attention 等高效实现完美兼容

高效注意力实现

为什么FlashAttention是长上下文推理的必备技术？GPU的SRAM（A100为20MB）带宽是HBM（1.6TB/s）的约100倍，但容量小得多。标准注意力需要实例化完整的n×n矩阵（128K×128K×2bytes=32GB，远超SRAM），导致频繁的HBM访问成为瓶颈。FlashAttention通过分块计算（Tiling）和在线Softmax（Online Softmax），避免实例化完整注意力矩阵，将HBM访问次数从O(n²)降至O(n²d/M)，在128K序列上实现2-4倍加速。

FlashAttention IO复杂度:
标准注意力 HBM访问: O(n²d + n²) → 128K序列约32TB数据传输
FlashAttention HBM访问: O(n²d²/M) → 128K序列约4TB数据传输 (M=20MB SRAM)
加速比: ≈ 8× (理论), 实测2-4× (受限于计算单元利用率)
天工实测: 128K序列Prefill, FlashAttention-2加速2.3×, 显存节省12×
🔬 FlashAttention IO复杂度 — 完整推导（A100具体数字）

1. 标准注意力的HBM访问次数推导
标准注意力需要实例化完整的n×n注意力矩阵S=QK^T，然后计算P=softmax(S)，最后O=PV。

步骤1: 从HBM读取Q, K (各n×d) → 计算S=QK^T (n×n) → 写入HBM
步骤2: 从HBM读取S (n×n) → 计算P=softmax(S) (n×n) → 写入HBM
步骤3: 从HBM读取P (n×n) 和 V (n×d) → 计算O=PV (n×d) → 写入HBM

总HBM访问 = Q读 + K读 + S写 + S读 + P写 + P读 + V读 + O写
= n²d + n²d + n² + n² + n² + n² + n²d + n²d
= 4n²d + 4n²
≈ 4n²d (当d >> 1时, d=128)


2. FlashAttention的HBM访问次数推导
FlashAttention将Q, K, V分为大小为B_r × d和B_c × d的块，在SRAM中完成全部计算。
设SRAM容量为M，块大小B_r = B_c = M / (4d)（留4d空间给Q_block, K_block, V_block, O_block）

对于Q的每个块(大小B_r × d):
对于K, V的每个块(大小B_c × d):
从HBM读取K_block, V_block → 在SRAM中计算 → 不写回HBM(只更新O的running统计量)

Q的块数 = ⌈n / B_r⌉, K/V的块数 = ⌈n / B_c⌉

总HBM访问 = Q读取(1次) + K读取(n/B_c次) + V读取(n/B_c次) + O写入(1次)
= n×d + (n/B_c)×(n×d) + (n/B_c)×(n×d) + n×d
= 2nd + 2n²d/B_c
≈ 2n²d/B_c (主导项)

代入 B_c = M/(4d):
FlashAttention HBM访问 ≈ 2n²d / (M/4d) = 8n²d²/M

4. 为什么实测加速只有2-4×而非8×？
• 计算瓶颈：当n很大时，计算量O(n²d)也开始占主导
• SRAM实际可用<20MB（CUDA kernel占用部分）
• Warp级并行效率：块大小128不是所有情况的最优值
• 天工实测：Prefill阶段(计算密集)加速2.3×，Decode阶段(IO密集)加速5-6×

# FlashAttention Tiling 伪代码 (简化版) def flash_attention(Q, K, V, Br=128, Bc=128): n, d = Q.shape O = zeros(n, d) # 输出 l = zeros(n) # running sum of exp (用于softmax归一化) m = full(n, -inf) # running max (用于numerical stability) Q_blocks = split(Q, Br) # n/Br 个块 K_blocks = split(K, Bc) # n/Bc 个块 V_blocks = split(V, Bc) # n/Bc 个块 for j in range(len(K_blocks)): Kj, Vj = K_blocks[j], V_blocks[j] # 从HBM加载到SRAM for i in range(len(Q_blocks)): Qi = Q_blocks[i] # 从HBM加载到SRAM Sij = Qi @ Kj.T / sqrt(d) # 在SRAM中计算 (Br×Bc) mij = rowmax(Sij) # 每行最大值 Pij = exp(Sij - mij) # 安全的exp li_new = exp(m - mij) * l[i] + rowsum(Pij) m_new = maximum(m[i], mij) O[i] = (l[i] * exp(m[i] - m_new) * O[i] + exp(mij - m_new) * Pij @ Vj) / li_new l[i], m[i] = li_new, m_new return O

说明：FlashAttention通过将注意力矩阵分块加载到SRAM计算，避免了将完整的n×n矩阵写入HBM。对于128K×128K的注意力矩阵（FP16下32GB），标准方法需要完整读写一次HBM，而FlashAttention将其分为约256×256的小块在SRAM中计算，显著减少HBM访问。

💡 天工FlashAttention配置：天工使用FlashAttention-2（比v1快20-30%），块大小设为128×128（匹配A100的SRAM容量）。对于搜索增强注意力注入的长检索上下文（可达55K tokens），FlashAttention是Prefill延迟控制在3秒以内的关键。

KV Cache 优化

Q₀ @ K₀^T = [[1,0], [0,1]] (单位矩阵)
S₀₀ = [[1,0], [0,1]] / 2 = [[0.5, 0], [0, 0.5]]

Step 3: Online Softmax统计量
rowmax(m₀₀) = [0.5, 0.5] (每行的最大值)
exp(S₀₀ - m₀₀) = [[exp(0), exp(-0.5)], [exp(-0.5), exp(0)]] = [[1, 0.6065], [0.6065, 1]]

P₀₀ @ V₀ = [[1, 0.6065], [0.6065, 1]] @ [[1,2,3,4], [5,6,7,8]]

此时O₀ = P₀₀ @ V₀ / l₀₀ = [[4.033/1.6065, ...], [5.607/1.6065, ...]]
= [[2.510, 3.510, 4.510, 5.510], [3.490, 4.490, 5.490, 6.490]]

继续j=1（Q₀与K₁的交互）：
S₀₁ = Q₀ @ K₁^T / 2 = [[0,0], [0,0]] / 2 = [[0,0], [0,0]] (Q₀的行与K₁的行正交)
m₀₁ = [0, 0], exp(S₀₁ - m₀₁) = [[1,1], [1,1]], l₀₁ = [2, 2]

Online Softmax合并：
m_new = max(m₀, m₀₁) = max([0.5,0.5], [0,0]) = [0.5, 0.5]
l_new = exp(0.5-0.5)×1.6065 + exp(0-0.5)×2 = 1.6065 + 1.213 = 2.8195

多模态注意力融合

多模态注意力融合的工程实现涉及多个关键优化。Kunlun在注意力计算中采用了FlashAttention的分块计算策略，将HBM访问次数降到理论下界。同时，通过KV Cache的分页管理和前缀共享技术，Kunlun在多轮对话场景下可以节省50%以上的显存占用。这些优化使得模型在实际部署中的推理效率大幅提升。

跨模态注意力的早期融合策略

天工多模态模型采用"早期融合"策略，在模型中间层就引入视觉token与文本token的交互，而非等到最后层才进行融合。这种设计使得模型能够更早地建立跨模态关联，配合Region Attention机制对图像不同区域分配差异化注意力权重，在OCRBench和DocVQA等需要精细视觉理解的任务上带来了显著的性能提升。

为什么天工采用"早期融合"策略？传统多模态模型（如Flamingo）在最后一个Transformer层才引入视觉token，导致模型只有1-2层能处理跨模态交互，无法建立深层次的视觉-语义关联。天工的早期融合在第8层（共80层）就引入视觉token，使后续72层都能进行跨模态注意力计算，在视觉问答和文档理解任务上的准确率比晚期融合高8-12%。

早期融合注意力计算:
Layer 1~7: 纯文本注意力 Attn(X_text, X_text, X_text)
Layer 8~80: 跨模态注意力 Attn([X_text; X_visual], [X_text; X_visual], [X_text; X_visual])
视觉token数量: n_visual = (H/p) × (W/p) (p=16, 图像分patch)
示例: 1024×1024图像 → 64×64=4096个视觉token (ViT-L/16)
文本+视觉: 5K文本token + 4K视觉token = 9K有效序列长度

说明：早期融合使得视觉特征在模型的每一层都能被文本token"查询"（Cross-Attention），建立丰富的跨模态关联。代价是注意力计算的有效序列长度增加——5K文本+4K视觉=9K tokens的注意力矩阵比纯文本5K大3.24倍（9²/5²）。天工的FlashAttention+GQA组合使这个开销可控。

💡 天工多模态配置：Skywork R1V4使用ViT-L/16作为视觉编码器，将图像分割为16×16的patch。对于高分辨率文档（如A4纸扫描件），采用动态分辨率策略：将图像分为全局缩略图（256×256）+ 高分辨率crop（512×512的4个区域），总计约2304个视觉token。
⚠️ 多模态注意力陷阱：① 视觉token膨胀——高分辨率图像产生大量token（4K图像可产生4096+ token），使注意力计算量和显存占用成倍增加。解决方案：Region Attention对非关键区域降采样、只对关键区域保持高分辨率；② 视觉-文本token比例失衡——视觉token远多于文本token时（如详细图像描述任务），文本信号被"淹没"。解决方案：对视觉token进行Pooling压缩（如从4096压缩到256）。

在天工多模态模型中，注意力机制还需处理跨模态信息融合。视觉 token 和文本 token 在统一的注意力空间中交互。

Region Attention：Skywork R1V4 引入了区域注意力机制，模型可以对图像的不同区域分配不同的注意力权重，实现更精细的视觉理解。配合多阶段裁剪策略，模型能主动"放大"图像中的关键区域。
  • 视觉-文本交叉注意力 — 文本 token 通过注意力机制查询视觉 token，获取图像信息
  • 动态分辨率 — 根据图像复杂度动态调整视觉 token 数量，避免信息浪费
  • 交错推理注意力 — 在 Thinking With Images 范式下，推理过程中图像 token 动态更新

⚠️ 注意力机制综合失败模式：① 长上下文"迷失中间"——即使使用YaRN扩展到128K，模型对中间位置信息的注意力仍会下降（从首尾的95%降至中间的60-70%）。解决方案：将关键信息放在首尾、或使用滑动窗口注意力；② 多模态注意力失衡——视觉token远多于文本token时，文本信号被淹没。解决方案：视觉token Pooling压缩、Region Attention选择性聚焦；③ GQA的KV Cache兼容性问题——旧版推理引擎不支持GQA的KV头压缩格式，需要升级vLLM/TensorRT-LLM；④ 搜索增强注意力的检索延迟——实时检索可能引入200-500ms延迟，解决方案：预检索+缓存、异步检索与Prefill并行。
