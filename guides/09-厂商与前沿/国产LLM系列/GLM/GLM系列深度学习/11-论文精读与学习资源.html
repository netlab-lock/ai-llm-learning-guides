11.1 核心论文列表

核心洞察：GLM 系列论文的演进路径清晰展示了从"知识增强预训练"（GLM-130B）到"对话模型"（ChatGLM）到"多模态+工具调用"（GLM-4）到"MoE+Agent"（GLM-5）的技术发展脉络。每篇论文都建立在前一篇的基础上，形成了渐进式创新而非颠覆式革命。

💡 阅读顺序建议：建议按 GLM-130B → ChatGLM → GLM-4 → GLM-5 的顺序阅读。GLM-130B 提出的 ABI（Autoregressive Blank Infilling）预训练范式是理解整个系列的基础——虽然后续版本放弃了该范式，但其设计思想（统一理解与生成）贯穿了整个 GLM 系列。
⚠️ 注意区分：GLM-130B 使用 ABI 预训练范式（自回归填空），而 ChatGLM/GLM-4/GLM-5 改用标准自回归（与 GPT 相同）。这是因为 ABI 的训练效率比纯自回归低约 20-30%。学习时务必注意这一架构变化，避免混淆。

11.2 论文精读指南

💡 精读方法论：读论文建议分三遍：第一遍通读摘要、引言和结论，了解"解决什么问题"和"怎么解决"；第二遍精读方法部分，关注公式推导和架构图；第三遍重点分析实验设计——消融实验往往比主实验更能揭示技术的真实贡献。对于 GLM 系列，特别关注每篇论文与前一版本的对比实验。

GLM-130B (ICLR 2023)

这是GLM系列的基础论文，建议重点阅读以下章节：

  • 第3节：General Language Model (GLM) 预训练框架，理解自回归填空任务
  • 第4节：Embedding Layer Gradient Shrink 技术，解决大模型训练不稳定问题
  • 第5节：INT4量化的实现细节，实现无损量化推理
  • 附录A：与GPT、BERT的架构对比分析，理解GLM的独特设计
🔬 公式(3) — ABI损失函数：GLM-130B的核心创新是将自回归生成和填空统一为一个损失函数：

L = -Σ log P(x_B | x_A) - Σ log P(x_span | x_A, x_{B,<t})

第一项是Part B的自回归生成损失，第二项是span内的填空损失。关键洞察：两个损失共享同一个Transformer backbone，通过不同的注意力掩码实现模式切换。消融实验表明，双任务联合训练比纯自回归在中文生成任务上BLEU-4提升2.3%，但训练时间增加约20%。
🔬 公式(8) — 梯度收缩技术（Gradient Shrink）：解决大模型训练中embedding层梯度爆炸问题：

∇W_emb' = α · ∇W_emb, 其中 α = ||∇W_small|| / ||∇W_emb||

原理：embedding层参数量占模型总参数的~25%，其梯度范数远大于其它层。通过将embedding梯度缩放到与小模型梯度相当的水平，使训练稳定性提升显著——在130B规模上，不使用该技术会导致约15%的训练步出现loss spike。
💡 Table 4消融实验解读：Table 4系统验证了各组件的贡献：(1) 移除ABI范式→中文生成BLEU下降2.3%；(2) 移除2D位置编码→长文本困惑度上升0.8；(3) 移除梯度收缩→训练不稳定（loss spike频率+15%）；(4) INT4量化→推理速度提升2.7倍，精度损失仅0.3%。核心结论：ABI和2D位置编码是GLM-130B最关键的创新。

GLM-4 Technical Report (2024.01)

GLM-4标志着从预训练模型到全能AI助力的转型，重点关注：

  • 第3节：多模态架构（GLM-4V），视觉编码器与语言模型的融合方案
  • 第4节：工具调用训练，多轮对话与Function Calling的统一训练
  • 第5节：长上下文扩展，从32K到1M token的技术路径
  • 第6节：安全对齐方法论，多维度安全评估框架
🔬 公式(5) — 工具调用的多任务损失：GLM-4将对话和工具调用统一为多目标优化：

L_total = λ₁·L_dialog + λ₂·L_tool + λ₃·L_arg

其中L_dialog是标准对话交叉熵，L_tool是工具选择损失（二分类：是否需要调用工具），L_arg是参数生成损失（序列到序列）。论文消融显示：λ₁=1.0, λ₂=0.5, λ₃=0.8时效果最优，工具调用准确率从67.2%提升至89.4%（+22.2pp），但纯对话能力下降约1.5%（MMLU从74.6→73.1）。
💡 Table 7安全评估方法解读：Table 7提出了六维度安全评估框架：(1) 有害内容拒绝率（目标>95%）(2) 隐私泄露率（目标<1%）(3) 偏见指数（目标<0.1）(4) 误拒率（目标<5%）(5) 对抗鲁棒性（攻击成功率<10%）(6) 幻觉率（目标<8%）。GLM-4在六维度上全部达标，尤其在有害内容拒绝率（98.2%）上超越GPT-4（96.5%）。

GLM-5 Technical Report (2025.06)

最新技术报告，是理解当前GLM系列的核心文献，重点关注：

  • MoE架构设计：专家路由策略与负载均衡机制
  • 国产芯片适配：华为昇腾910C的优化方案和性能对比
  • Agent训练：工具调用和多步骤推理的训练方法论
  • 安全性设计：对齐训练和安全过滤机制的工程实践
  • 基准测试：详细的评估方法论和结果分析
🔬 公式(4) — MoE路由的Sigmoid门控：GLM-5采用Sigmoid门控替代传统Softmax路由：

g_i(x) = σ(W_g · x + b_i), 其中σ为Sigmoid函数

与传统Softmax路由（Σg_i=1）不同，Sigmoid门控允许多个专家同时激活（Σg_i可>1），使模型在需要时可以调用更多专家处理复杂任务。论文显示：在推理任务上，Sigmoid路由比Softmax路由提升3.7%（GSM8K 84.2%→87.9%），但推理延迟增加约15%（因为平均激活专家数从2.0升至2.8）。
💡 Table 3 MoE消融实验解读：Table 3对比了不同MoE配置：(1) 8专家→16专家：MMLU提升2.1%但推理速度下降35%；(2) Top-2路由→Sigmoid路由：推理任务+3.7%，通用任务-0.8%；(3) 加入负载均衡损失：专家利用率从62%提升至91%；(4) 激活参数从7B→14B：整体性能提升5.2%。核心结论：GLM-5选择16专家+Sigmoid路由+激活14B是最优性价比点。

11.3 GitHub 代码仓库

核心洞察：GLM 的开源策略是"全栈开源"——从模型权重（HuggingFace）到推理代码（GitHub）到训练框架（BMTrain），形成了完整的开源生态。这与部分厂商仅开源推理代码的策略不同，使得社区可以在 GLM 基础上进行深度定制和训练。

💡 入门推荐：初学者建议从 THUDM/ChatGLM-6B 仓库开始——它文档完善、社区活跃、issue 回复及时。仓库中的 cli_demo.py 和 web_demo.py 可以在本地快速跑通一个对话 demo，建立直观感受后再深入源码。
⚠️ 版本兼容性注意：GLM-4 及以后版本的推理代码需要 transformers >= 4.40。如果使用旧版 transformers 加载 GLM-4 模型，可能会遇到 KeyError: 'glm4' 错误。建议在各仓库的 README 中确认依赖版本后再安装。

11.4 HuggingFace 模型资源

核心洞察：GLM 的 HuggingFace 模型资源覆盖了从 9B（GLM-4-9b）到 32B（GLM-5-32b）再到 MoE 架构（GLM-5.2-moe，激活 14B）的全尺寸范围。对于研究者而言，最有价值的是 GLM-5.2-moe——它是少数开源的 MoE 模型之一，可以用于研究专家路由、负载均衡等 MoE 核心问题。

💡 模型选择建议：如果资源有限（如单卡 24GB），推荐使用 GLM-4-9b-chat（INT4 量化后约 6GB）。如果需要研究 MoE 路由机制，GLM-5.2-moe 是唯一开源的选择。注意 GLM-5.2-moe 虽然总参数量大，但激活参数量仅 14B，推理成本可控。
⚠️ 量化精度注意：GLM-4-9b 的 INT4 量化在大部分任务上损失 <1%，但在数学推理（GSM8K）和代码生成（HumanEval）任务上可能损失 3-5%。如果应用场景涉及数学或代码，建议在目标任务上验证量化后的效果再部署。

GLM 论文学习的失败模式与调试

核心洞察：GLM 论文学习的典型失败模式包括——(1) 不理解 ABI 预训练范式（Autoregressive Blank Infilling）的数学原理，导致无法理解 GLM-130B 与 GPT/BERT 的本质区别；(2) 忽略 GLM 的位置编码方案（2D 位置编码），导致无法理解其长上下文能力；(3) 对 MoE 路由机制的理解停留在表面，无法复现 GLM-5 的负载均衡策略。

失败模式1：ABI 范式理解偏差

症状：认为 GLM-130B 只是"BERT + GPT 的简单组合"。

正确理解：ABI 的核心创新是将文档分为 Part A（双向注意力，被遮盖的部分）和 Part B（自回归生成，遮盖的内容），通过统一的掩码注意力实现两种模式的融合。数学描述：

ABI 注意力掩码：
M_{ij} = 1 如果 i 和 j 都在 Part A（双向）
M_{ij} = 1 如果 i 在 Part B 且 j 在 Part A 或 j ≤ i（因果）
M_{ij} = 0 其他情况

关键：Part A 内部双向（理解），Part B 因果（生成），Part B 可以关注 Part A（条件生成）

失败模式2：2D 位置编码忽略

症状：不理解 GLM-130B 如何处理被遮盖 span 内的位置关系。

正确理解：GLM 使用 2D 位置编码——第一维编码 token 在文档中的绝对位置，第二维编码 token 在 span 内的相对位置。这使得模型既能感知全局位置，又能感知 span 内的局部顺序。

💡 实用技巧：精读 GLM-130B 论文时，重点关注 Figure 2（ABI 示意图）和 Figure 3（2D 位置编码示意图）。这两个图包含了论文最核心的创新——理解了它们，就理解了 80% 的论文贡献。
⚠️ 注意事项：GLM-4 及以后的版本已放弃 ABI 范式，改用标准自回归（与 GPT 相同）。这是因为 ABI 的训练效率比纯自回归低约 20-30%（需要同时优化两种注意力模式）。学习时注意区分：GLM-130B 用 ABI，ChatGLM/GLM-4/GLM-5 用标准自回归。
🔬 深入探讨：GLM 的 2D 位置编码与 Transformer-XL 的相对位置编码有本质区别——Transformer-XL 使用基于 token 间距离的相对位置，而 GLM 使用基于"文档位置 + span 内位置"的绝对+相对混合位置。这使得 GLM 在处理被遮盖的 span 时能保持 span 内的顺序信息，而 Transformer-XL 做不到这一点。
