📝 08 · Word2Vec — 词嵌入革命

2013 · Tomas Mikolov 等 (Google) · "king - man + woman = queen" · NLP 向量化时代

一、背景与动机

在 Word2Vec 之前，NLP 中词语用独热编码(One-Hot)表示：每个词是一个长向量，只有对应位置是 1。问题：① 维度爆炸(10万词→10万维) ② 任意两个词的距离相同(正交) ③ 无法表达语义关系("好"和"优秀"的距离等于"好"和"桌子")。

Mikolov 等人的突破：用一个浅层神经网络，把词映射到低维稠密向量空间(如300维)，使得语义相近的词向量也相近。这就是 Word2Vec。

💡 一句话总结：Word2Vec 让计算机第一次"理解"了词义——king 和 queen 的向量方向一致(都是皇室)，car 和 automobile 几乎重合(同义词)。

二、名字由来

💡 通俗类比：Word2Vec 就是"Word to Vector"——把单词变成向量。就像把一个人的"性格"用几个数字表示(内向0.7, 幽默0.3, 勤奋0.9)——虽然简化了，但捕捉了核心特征。
⚠️ 常见误区：Word2Vec 不是一种"算法"，而是一个工具包名。它包含两种模型：CBOW(从上下文预测中心词)和 Skip-gram(从中心词预测上下文)。两者目标相反，效果类似。
🔬 深入探讨：Word2Vec 的词向量有一个神奇的性质：向量运算能捕捉语义关系。"king - man + woman ≈ queen"是最著名的例子。这不是巧合——训练目标隐式地学到了这些关系，虽然从未被显式教导。

Word(词) + 2(to 的谐音) + Vec(Vector 向量) = "词到向量"。这是程序员常见的命名风格(类似 py2exe, img2txt)。

Embedding(嵌入)：数学术语，指把一个空间映射到另一个空间。词嵌入 = 把词嵌入到向量空间。

三、核心原理

💡 通俗类比：Skip-gram 就像"填空题"——给你一个词(如"苹果")，让你预测它周围可能出现什么词("吃"、"红色"、"手机")。经常出现在相似上下文中的词，会被映射到相近的向量。
⚠️ 常见误区：Word2Vec 的"上下文窗口"不是越大越好。太大的窗口会让词向量捕获"主题"信息(如"苹果"和"水果"更近)，太小会捕获"语法"信息(如"苹果"和"吃"更近)。窗口大小决定了你学到什么样的语义。
🔬 深入探讨：负采样(Negative Sampling)是 Word2Vec 训练高效的关键——不计算整个词表的 softmax(词表可能有百万词)，而是随机采样几个"负例"。这把训练复杂度从 O(V) 降到 O(K)——V是词表大小，K是负样本数(通常5-20)。

3.1 分布式假说 (Distributional Hypothesis)

"一个词的含义由它的上下文决定"——J.R. Firth (1957): "You shall know a word by the company it keeps."

如果两个词经常出现在相似的上下文中，它们的语义就相似。

3.2 CBOW 模型

CBOW (Continuous Bag of Words): 用上下文词预测中心词 上下文窗口(窗口大小=2): "the" "cat" [___] "on" "the" ↑ 预测 "sat" 网络结构: 上下文词 → 查词嵌入表 → 平均 → 隐藏层 → Softmax → 预测中心词 (one-hot) (300维) (300维) (300×V) (V维) 目标: 让预测的词和真实词的概率分布接近 损失: 交叉熵 Loss = -log P(center|context)

CBOW 完整 PyTorch 实现

import torch
import torch.nn as nn
import torch.nn.functional as F

class CBOW(nn.Module):
    """CBOW模型：用上下文词预测中心词，上下文向量取平均"""
    def __init__(self, vocab_size, embed_dim, num_neg_samples=5):
        super().__init__()
        self.vocab_size = vocab_size
        self.embed_dim = embed_dim
        self.num_neg_samples = num_neg_samples
        # 输入嵌入层：上下文词向量(将被平均)
        self.context_embed = nn.Embedding(vocab_size, embed_dim)
        # 输出嵌入层：目标词向量(用于负采样打分)
        self.target_embed = nn.Embedding(vocab_size, embed_dim)
        # 初始化：均匀分布[-0.5/dim, 0.5/dim]
        self.context_embed.weight.data.uniform_(-0.5/embed_dim, 0.5/embed_dim)
        self.target_embed.weight.data.uniform_(-0.5/embed_dim, 0.5/embed_dim)

    def forward(self, context_words, pos_target, neg_targets):
        """
        context_words: [batch_size, 2*window]  上下文词索引
        pos_target:    [batch_size]            中心词(正样本)索引
        neg_targets:   [batch_size, k]         负样本词索引
        """
        # 1. 查表获取上下文词嵌入并取平均 → [batch_size, embed_dim]
        context_emb = self.context_embed(context_words)  # [B, 2W, D]
        context_mean = context_emb.mean(dim=1)           # [B, D]

        # 2. 正样本打分：中心词向量与上下文平均向量的内积
        pos_target_emb = self.target_embed(pos_target)   # [B, D]
        pos_score = (context_mean * pos_target_emb).sum(dim=1)  # [B]
        pos_loss = -F.logsigmoid(pos_score)               # -log σ(pos_score)

        # 3. 负采样：随机采样k个非上下文词作为负样本
        neg_target_emb = self.target_embed(neg_targets)  # [B, k, D]
        # 计算每个负样本与上下文平均向量的内积
        neg_score = torch.bmm(
            neg_target_emb,                              # [B, k, D]
            context_mean.unsqueeze(2)                    # [B, D, 1]
        ).squeeze(2)                                       # [B, k]
        neg_loss = -F.logsigmoid(-neg_score).sum(dim=1)  # -log σ(-neg_score)

        # 4. 总损失 = 正样本损失 + 负样本损失
        loss = (pos_loss + neg_loss).mean()
        return loss

    def get_embeddings(self):
        """返回训练好的词向量(输入嵌入)"""
        return self.context_embed.weight.data


# --- 训练示例 ---
vocab_size = 10000   # 词表大小
embed_dim = 300      # 词向量维度
window = 2          # 上下文窗口大小
k = 5             # 负样本数
lr = 0.001       # 学习率

model = CBOW(vocab_size, embed_dim, num_neg_samples=k)
optimizer = torch.optim.Adam(model.parameters(), lr=lr)

# 模拟一个batch的训练
batch_size = 512
context = torch.randint(0, vocab_size, (batch_size, 2*window))  # 上下文词
target = torch.randint(0, vocab_size, (batch_size,))              # 中心词
neg_samples = torch.randint(0, vocab_size, (batch_size, k))       # 负样本

loss = model(context, target, neg_samples)
loss.backward()
optimizer.step()
print(f"Loss: {loss.item():.4f}")  # 初始约 3.9 (≈ln(10000/(k+1)))

3.3 Skip-gram 模型

Skip-gram: 用中心词预测上下文词 (CBOW 的逆) 中心词: "sat" 预测: "the", "cat", "on", "the" 中心词 → 查词嵌入表 → 隐藏层 → Softmax → 预测上下文词 (one-hot) (300维) (300×V) (V维) 优势: 训练数据更充足(每个词对都是一个训练样本) 对低频词效果更好
Skip-gram 条件概率:
P(w_{t+j} | w_t) = exp(v'_{w_{t+j}} · v_{w_t}) / Σ_{w=1}^{V} exp(v'_w · v_{w_t})
其中 v_{w_t} 是中心词向量, v'_{w_{t+j}} 是上下文词向量, j∈[-c,c], j≠0
Skip-gram 目标函数(对数似然):
L = (1/T) Σ_{t=1}^{T} Σ_{-c≤j≤c, j≠0} log P(w_{t+j} | w_t)
最大化上下文词的对数概率 → 等价于最小化负对数似然
负采样近似(将多分类转化为二分类):
L_NS = log σ(v'_{w_O} · v_{w_I}) + Σ_{i=1}^{k} E_{w_i ~ P_n(w)} [log σ(-v'_{w_i} · v_{w_I})]
其中 k=5~20 为负样本数, P_n(w) ∝ freq(w)^{0.75} 为噪声分布
梯度计算:
∂L_NS/∂v_{w_I} = [σ(v'_{w_O}·v_{w_I}) - 1] · v'_{w_O} + Σ_{i=1}^{k} [σ(v'_{w_i}·v_{w_I})] · v'_{w_i}
∂L_NS/∂v'_{w_O} = [σ(v'_{w_O}·v_{w_I}) - 1] · v_{w_I}
∂L_NS/∂v'_{w_i} = σ(v'_{w_i}·v_{w_I}) · v_{w_I} (对每个负样本w_i)
💡 梯度直觉：正样本梯度[σ(·)-1]·v'：当模型正确预测时σ→1，梯度趋近0；错误时σ→0，梯度为-v'，推动中心词向量向上下文词靠近。负样本梯度σ(·)·v：推动中心词向量远离噪声词。

3.4 训练技巧

Softmax 的分母需要遍历整个词表(10万+)，计算量巨大。两个关键优化：

技巧原理效果
负采样(Negative Sampling)不计算完整 Softmax，只区分正样本和随机负样本训练速度 ×1000
层次 Softmax用二叉树代替平坦 Softmax复杂度 O(V) → O(log V)
负采样损失:
J = log σ(v'ₒ · vᵤ) + Σ E[log σ(-v'ₙ · vᵤ)]
正样本得分↑ + 负样本得分↓
其中 vᵤ 是中心词向量, v'ₒ 是上下文词向量

四、技术细节

💡 通俗类比：训练 Word2Vec 就像训练一个"猜词游戏"AI——给它看大量文本，让它反复练习"根据上下文猜词"。练得越多，它对词与词之间关系的理解就越深。
⚠️ 常见误区：Word2Vec 的词向量是"静态"的——"苹果"只有一个向量，无论它是"吃苹果"还是"苹果手机"中的苹果。这种"一词一义"的局限性后来被 ELMo(上下文相关)和 BERT(双向上下文)解决了。
🔬 深入探讨：Word2Vec 的训练目标(预测上下文)和后来 BERT 的训练目标(Masked LM)有异曲同工之妙——都在利用"上下文"学习词义。区别在于 Word2Vec 是"浅层"(一个线性层)，BERT 是"深层"(12/24层 Transformer)。

4.1 预训练词向量的特性

Word2Vec 向量的神奇代数: king - man + woman ≈ queen Paris - France + Italy ≈ Rome walking - walked + swam ≈ swimming 原理: 词向量空间中存在线性关系 方向1: 性别 (man→woman, king→queen) 方向2: 国家→首都 (France→Paris, Italy→Rome) 方向3: 时态 (walk→walked, go→went)

五、使用场景

💡 通俗类比：Word2Vec 之于 NLP，就像"拼音"之于中文学习——它是最基础的"表征"，让机器第一次"理解"了词与词之间的关系。没有词向量，就没有后来的一切 NLP 进展。
⚠️ 常见误区：Word2Vec 在2024年已很少直接使用(被BERT等取代)，但"词嵌入"的思想是所有现代 NLP 模型的基础。Embedding 层——把离散的token映射为连续向量——就是 Word2Vec 思想的直接继承。
🔬 深入探讨：Word2Vec 的成功启发了"万物皆可 Embedding"——用户 Embedding(推荐系统)、图节点 Embedding(Graph Neural Networks)、甚至蛋白质序列 Embedding。把离散实体映射到连续向量空间的思想，已经超越了 NLP 的范畴。
  • NLP 基础设施：几乎所有 NLP 任务的第一步——把文本变成向量
  • 推荐系统：把 Item2Vec(类似思想)用于商品/用户嵌入
  • 图嵌入：DeepWalk、Node2Vec 把 Word2Vec 思想用于图节点
  • 搜索引擎：查询和文档的语义匹配

六、相似技术对比

💡 通俗类比：Word2Vec vs GloVe vs FastText 就像三种不同的"学外语"方式——Word2Vec 通过"读大量文章"学(预测上下文)，GloVe 通过"查词频统计"学(共现矩阵分解)，FastText 通过"拆字根"学(子词信息)。
⚠️ 常见误区：不要以为"越新的越好"。在某些任务中(如词类比)，Word2Vec 的效果并不比 BERT 差。"够用"就好——用大炮打蚊子是浪费资源。
🔬 深入探讨：GloVe 和 Word2Vec 在数学上有等价性——Levy & Goldberg(2014)证明了 Skip-gram 隐式地在分解一个PMI矩阵。这意味着两种看似不同的方法其实在做同一件事——科学中"殊途同归"的现象比比皆是。

七、关联技术

💡 通俗类比：Word2Vec → ELMo → BERT 的演进就像"照片"→"视频"→"3D全息"——从静态词向量，到上下文相关的动态词向量，再到双向深层上下文表示。每一步都是对"理解"的加深。
⚠️ 常见误区：Word2Vec 的"king - man + woman ≈ queen"虽然很酷，但也暴露了词向量的偏见——训练数据中的性别、种族偏见会被编码进向量。这不是 Word2Vec 的bug，而是数据的"镜子"。
🔬 深入探讨：Word2Vec 的另一个意外发现是：词向量可以跨语言对齐。通过少量双语词典，可以把中文词向量和英文词向量映射到同一空间——这启发了多语言BERT(mBERT)和XLM-R的跨语言能力。
  • Transformer(模型14)：Transformer 的 Token Embedding 层就是词嵌入
  • BERT(模型15)：上下文相关的动态词嵌入，解决了 Word2Vec 一词多义问题
  • 位置编码：Transformer 需要额外的位置编码，因为嵌入层本身不包含位置信息
  • Skip-thought / Doc2Vec：将 Word2Vec 扩展到句子/文档级别

八、实际效果

💡 通俗类比：Word2Vec 的300维向量就像"300个特征维度"描述一个词——每个维度可能对应某种隐含的语义特征(虽然我们不知道每个维度具体代表什么)。
⚠️ 常见误区：Word2Vec 在词类比任务上表现很好(如 king-man+woman=queen)，但这不等于它"理解"了语义。它只是学到了统计共现模式——"理解"和"统计"之间的界限是 AI 领域最深刻的哲学问题之一。
🔬 深入探讨：Word2Vec 训练的词向量维度(通常100-300)是经验选择，没有理论最优解。太小捕获不了足够的语义信息，太大则包含噪声且计算昂贵。这个"维度选择"问题在所有 Embedding 场景中都存在。
任务One-Hot + 传统方法Word2Vec 特征提升
命名实体识别(F1)~85%~91%+6%
情感分析(准确率)~80%~87%+7%

🔬 Skip-gram的PMI等价性（Levy & Goldberg 2014证明）： Skip-gram + 负采样隐式地分解了词-上下文共现矩阵的PMI（逐点互信息）: w·c ≈ PMI(w,c) - log k。 其中k是负样本数。这就是为什么词向量存在线性关系——因为PMI矩阵中语义相关的词对共享相似的模式。 当k=5时，log k ≈ 1.6，这意味着词向量内积编码了去偏后的PMI值。 GloVe显式分解log(共现矩阵)，而Skip-gram通过预测任务隐式达到相同效果——殊途同归。

失败模式与局限性

⚠️ 失败模式1：低频词向量质量差 当语料中某个词的出现次数过少(如<50次)，其词向量无法获得充分的梯度更新，导致语义不准确。

量化数据：在Wikipedia语料上训练Word2Vec(300维,窗口5)，不同频率词的向量质量差异显著：
词频区间平均余弦相似度(人工标注)类比任务准确率问题示例
>10,000次(高频)0.7872%向量质量稳定
500-10,000次(中频)0.6558%基本可用
50-500次(低频)0.4131%"ephemeral"的向量更接近"temporary"而非"transient"
<50次(极低频)0.1812%几乎随机，与任何词的相似度都接近0

根本原因：负采样损失中，每个词对只产生1次正样本更新。低频词作为正样本出现的次数极少，其嵌入向量的更新步数不足(如出现20次的词，最多获得约20×window_size≈100次有效更新)。

正确做法： ① 设置min_count=5过滤极低频词，或用FastText的子词机制增强； ② 增大语料规模——同样的词在更大语料中出现更多次； ③ 对低频词使用更多训练轮次(epoch)或降低学习率衰减速度； ④ 使用FastText替代：子词组合让低频词"借用"字符级特征。
⚠️ 失败模式2：多义词问题(Polysemy) Word2Vec为每个词分配唯一向量，无法区分同一词的不同语义。这导致向量是多个含义的"平均"，在特定上下文中产生偏差。

具体案例："bank"在Word2Vec中学到的是"河岸"和"银行"的混合向量。
查询目标Word2Vec最近邻(错误)期望结果偏差原因
bank(金融含义)river, stream, water, creekfinance, money, deposit被"河岸"含义拉偏
bank(河岸含义)finance, banking, deposit, creditriver, stream, shore被"银行"含义拉偏

量化影响：在CoNLL-2003命名实体识别任务中，多义词导致的错误占实体分类错误的23%。"Apple"被错误分类为"水果"而非"公司"的概率为34%。

数学解释：设词w有n种含义，每种含义对应一个理想向量v₁,v₂,...,vₙ。Word2Vec学到的向量v_w是这些向量的加权平均：v_w = Σᵢ p(sᵢ)·vᵢ，其中p(sᵢ)是该含义在训练语料中的出现比例。这意味着向量指向所有含义的"重心"。

正确做法： ① 使用上下文相关模型(ELMo/BERT)——动态根据上下文生成不同向量； ② 词义消歧(Word Sense Disambiguation)作为预处理步骤； ③ 在训练时加入主题标签(LDA)作为额外特征； ④ 领域专用训练：在金融语料上训练的"bank"向量会偏向金融含义。

9.1 Skip-gram 模型实现

import torch
import torch.nn as nn

class SkipGram(nn.Module):
    def __init__(self, vocab_size, embed_dim):
        super().__init__()
        self.center_embed = nn.Embedding(vocab_size, embed_dim)
        self.context_embed = nn.Embedding(vocab_size, embed_dim)

    def forward(self, center, context, neg_samples):
        center_emb = self.center_embed(center)
        context_emb = self.context_embed(context)
        neg_emb = self.context_embed(neg_samples)

        pos_score = torch.sum(center_emb * context_emb, dim=1)
        pos_loss = -torch.log(torch.sigmoid(pos_score) + 1e-10)

        neg_score = torch.bmm(neg_emb, center_emb.unsqueeze(2)).squeeze()
        neg_loss = -torch.log(torch.sigmoid(-neg_score) + 1e-10).sum(dim=1)

        return (pos_loss + neg_loss).mean()

from collections import Counter
import numpy as np

def build_vocab(corpus, min_count=5):
    word_counts = Counter()
    for sentence in corpus:
        word_counts.update(sentence)
    vocab = {w: i for i, (w, c) in enumerate(
        word_counts.items() if c >= min_count
    )}
    return vocab

def generate_skipgram_pairs(corpus, vocab, window_size=5):
    pairs = []
    for sentence in corpus:
        indices = [vocab[w] for w in sentence if w in vocab]
        for i, center in enumerate(indices):
            for j in range(max(0, i - window_size),
                         min(len(indices), i + window_size + 1)):
                if i != j:
                    pairs.append((center, indices[j]))
    return pairs

9.3 词向量类比实验

def word_analogy(model, word2idx, idx2word, a, b, c, top_k=5):
    # 例如: king - man + woman = queen
    vec_a = model.center_embed.weight[word2idx[a]]
    vec_b = model.center_embed.weight[word2idx[b]]
    vec_c = model.center_embed.weight[word2idx[c]]
    target = vec_a - vec_b + vec_c

    all_vecs = model.center_embed.weight.detach()
    target_norm = target / target.norm()
    all_norm = all_vecs / all_vecs.norm(dim=1, keepdim=True)
    similarities = (all_norm @ target_norm).detach().numpy()

    exclude = {word2idx[a], word2idx[b], word2idx[c]}
    for idx in exclude:
        similarities[idx] = -1

    top_indices = similarities.argsort()[-top_k:][::-1]
    for idx in top_indices:
        print(f"  {idx2word[idx]}: {similarities[idx]:.4f}")

▶显示答案
✅ 参考答案与详解
  1. 核心原理: CBOW(Context-Bag-of-Words)用周围词的向量的平均来预测中心词(类似"完形填空")，训练速度快但对罕见词效果一般。Skip-gram用中心词预测周围每个上下文词(类似"一词多用")，每个中心词产生多个训练样本。Skip-gram在语料库较大时表现更好，因为：(1)大数据Skip-gram能学到更好的罕见词表示；(2)每个中心词生成更多训练信号；(3)罕见词有足够机会被正确预测。CBOW训练更快因为一次更新同时使用所有上下文信息。
    关键要点: (1)CBOW预测中心词；(2)Skip-gram预测上下文；(3)大数据Skip-gram更好；(4)小数据CBOW更稳定；(5)CBOW训练更快。
    实际案例: Google News预训练词向量使用Skip-gram+负采样在1000亿词上训练。在类比任务(king-man+woman=queen)上Skip-gram优于CBOW约5-10%。
  2. 核心原理: 原始Softmax需要对所有词计算概率并归一化(计算量O(V), V=词表大小≈百万)，每次更新都需要计算这百万次。层次Softmax用Huffman树将复杂度降到O(logV)——每个词对应树的一条路径，只需计算路径上约log₂(V)≈20个节点。负采样更简单：将多分类问题转化为二分类问题——判断一个词对是"真实上下文对"还是"负样本对"，只需计算5-20个负样本加1个正样本，大幅减少计算量。负采样效果更好因为对于罕见词，少量负样本已足够提供学习信号。
    关键要点: (1)原始Softmax O(V)太慢；(2)层次Softmax O(logV)；(3)负采样O(k+1)二分类；(4)负采样效果更好；(5)两者都是近似方法。
    实际案例: Word2Vec论文证明负采样在类比任务和罕见词表示上均优于层次Softmax。Gensim库的Word2Vec实现默认使用负采样。
  3. 核心原理: 线性关系出现的核心原因是Word2Vec学到的词向量近似编码了词的"语义角色"。从共现统计角度看："King"和"Man"的上下文差异(δ₁)与"Queen"和"Woman"的上下文差异(δ₂)高度相似——它们只在"性别"相关词上有差异，其余语义关系(王室、权力、领导等)相同。Skip-gram的条件概率logP(w_context|w_center)近似编码了共现比例。当两个词对的共现模式相似时，它们的向量差也相似：v_King - v_Man ≈ v_Queen - v_Woman。
    关键要点: (1)共现模式编码在向量中；(2)相似语义关系的向量差也相似；(3)类比推理就是向量加减；(4)实际上是词移距(Word Mover's Distance)的近似；(5)关系类比任务是词向量质量的重要评测。
    实际案例: Word2Vec在类比任务上达到75%+准确率。[v_paris - v_france + v_italy ≈ v_rome]、[v_happy - v_sad + v_angry ⇒ v_upset]等关系都被成功捕获。
  4. 核心原理: Word2Vec为每个词分配一个固定向量，无法处理多义性——例如"bank"(河岸/银行)只有一个向量，它编码了两种含义的模糊混合。这在含有大量多义词的语言中尤其严重。BERT通过Transformer编码器动态计算每个词在特定上下文中的表示："river bank"和"bank account"中的"bank"会得到不同的向量。这种"上下文相关表示"(Contextual Embedding)解决了多义性问题，但也失去了Word2Vec的简洁性——无法预先计算所有词的单向量。
    关键要点: (1)Word2Vec一个词一个向量；(2)多义词被模糊混合；(3)BERT上下文相关表示；(4)动态计算vs静态编码；(5)ELMo也解决了多义性问题。
    实际案例: "苹果"在"吃苹果"和"苹果公司"中有完全不同的含义，Word2Vec无法区分。BERT会为这两种用法生成明显不同的向量表示，在下游任务(如NER)中显著提升了性能。
  5. 核心原理: Skip-gram原始目标函数(对数似然)：L = (1/T)∑ₜ∑_{-c≤j≤c,j≠0} log P(wₜ₊ⱼ|wₜ)。其中P(w_O|w_I) = exp(v'ᵀ_U · v_I) / ∑ᵥexp(v'ᵀ_w · v_I)。梯度∂L/∂v_I需要对全部词表求和计算(百万次)，不实用。负采样将其转化为二分类：L = logσ(v'ᵀ_wO · v_I) + ∑ᵢ₌₁ᵏE_{wᵢ~P_n(w)}[logσ(-v'ᵀ_wᵢ · v_I)]。这里k个负样本从噪声分布P_n(w)中采样(通常设为词频的3/4次方)。梯度计算只需对正样本和k个负样本求和，与词表大小无关。
    关键要点: (1)原始目标需要对百万词表计算softmax；(2)负采样转化为二分类问题；(3)k通常取5-20；(4)噪声分布P_n(w)∝freq(w)^0.75；(5)负采样梯度与词表大小无关故高效。
    实际案例: 在Google News 1000亿词上训练Word2Vec，原始Softmax一次更新需计算100万个词的概率——而负采样只需计算6个(1正+5负)，加速约16万倍！

解题思路: Skip-gram核心是滑动窗口生成(中心词,上下文)对，负采样转化为二分类任务。

import numpy as np
from collections import Counter

# 1. 数据预处理
text = "the cat sat on the mat the dog sat on the log the cat chased the dog"
words = text.split()
vocab = set(words)
word2idx = {w: i for i, w in enumerate(vocab)}
idx2word = {i: w for w, i in word2idx.items()}
V = len(vocab)

# 2. 生成(中心词, 上下文)对
def generate_pairs(words, window=2):
    pairs = []
    for i, center in enumerate(words):
        for j in range(max(0, i-window), min(len(words), i+window+1)):
            if j != i:
                pairs.append((word2idx[center], word2idx[words[j]]))
    return pairs

pairs = generate_pairs(words)

# 3. 负采样分布 P_n(w) ∝ freq(w)^0.75
word_counts = Counter(words)
freqs = np.array([word_counts[idx2word[i]] ** 0.75 for i in range(V)])
noise_dist = freqs / freqs.sum()

# 4. 训练
np.random.seed(42)
embed_dim = 10
W = np.random.randn(V, embed_dim) * 0.01   # 输入嵌入
W_prime = np.random.randn(V, embed_dim) * 0.01  # 输出嵌入

lr, k = 0.01, 3
for epoch in range(500):
    total_loss = 0
    for center, context in pairs:
        pos_score = 1 / (1 + np.exp(-W_prime[context] @ W[center]))
        neg_samples = np.random.choice(V, size=k, p=noise_dist)
        neg_score = 1 / (1 + np.exp(-W_prime[neg_samples] @ W[center]))
        total_loss += -np.log(pos_score) - np.sum(np.log(1 - neg_score))
        grad_pos = pos_score - 1
        grad_neg = neg_score
        W[center] -= lr * (grad_pos * W_prime[context] + np.sum([grad_neg[i] * W_prime[neg_samples[i]] for i in range(k)], axis=0))
        W_prime[context] -= lr * grad_pos * W[center]
        W_prime[neg_samples] -= lr * np.outer(grad_neg, W[center])

# 5. 类比推理: king - man + woman = queen
v = lambda w: W[word2idx[w]]
analogies = [('king','man','woman'), ('cat','dog','log')]
a, b, c = 'king', 'man', 'woman'
target = v(a) - v(b) + v(c)
sims = [(w, np.dot(target, v(w)) / (np.linalg.norm(target)*np.linalg.norm(v(w)))) for w in vocab]
print(f"{a} - {b} + {c} ≈", sorted(sims, key=lambda x: -x[1])[:3])

关键知识点: (1)Skip-gram用窗口滑动生成训练对；(2)负采样转化为二分类任务；(3)P_n(w)∝freq(w)^0.75采样负样本；(4)sigmoid函数计算正/负样本概率；(5)向量空间中的线性关系反映语义关系。
