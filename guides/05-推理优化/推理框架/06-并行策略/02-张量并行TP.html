✂️ 张量并行 TP

把每一层的权重矩阵"切开"分给多张 GPU — 同机多卡的首选方案

✂️ Tensor Parallelism — 把一块大蛋糕切成几份 想象每一层的权重矩阵 W 是一块大蛋糕: 单卡: 一个人吃一块大蛋糕 → 吃不下（显存不够） TP=2: 把蛋糕切成两半，两个人各吃一半: ┌──────────────────┐ ┌─────────────┐ ┌─────────────┐ │ │ → │ │ │ │ │ 完整的 W │ │ W 左半 │ │ W 右半 │ │ (太大了) │ │ (GPU 0) │ │ (GPU 1) │ │ │ │ │ │ │ └──────────────────┘ └─────────────┘ └─────────────┘ 每张 GPU 只存一半的权重，计算一半的结果。 最后用 AllReduce 把两半结果加起来 = 完整结果。

二、列切分 vs 行切分

矩阵切分有两种方式，在 Transformer 中配合使用：

2.1 列切分（Column Parallel）

列切分: 按"列"把矩阵切成左右两半 输入 X: [n × d] (n 个 token，每个 d 维) 权重 W: [d × d'] 切成 [d × d'/2] 和 [d × d'/2] GPU 0: Y_left = X × W_left ← 计算左半部分输出 GPU 1: Y_right = X × W_right ← 计算右半部分输出 结果: [Y_left, Y_right] ← 两半拼起来就是完整结果！ 不需要 AllReduce！（结果天然互补）

2.2 行切分（Row Parallel）

行切分: 按"行"把矩阵切成上下两半 输入 X: [n × d] 切成 [n × d/2] 和 [n × d/2] 权重 W: [d × d'] 切成 [d/2 × d'] 和 [d/2 × d'] GPU 0: Y_left = X_left × W_top ← 左输入 × 上半权重 GPU 1: Y_right = X_right × W_bottom ← 右输入 × 下半权重 结果: Y = Y_left + Y_right ← 需要 AllReduce 求和！

2.3 Transformer 中的 TP 组合

一个 Transformer 层中的 TP 切分方式 ┌──────────────────────────────────────────────────────────┐ │ Attention 层 │ │ │ │ Q, K, V 投影: 按 head 切分（天然的列切分） │ │ ┌─────────┐ ┌──────────┐ ┌──────────┐ │ │ │ X │ ──→ │ Q0,K0,V0 │ │ Q1,K1,V1 │ │ │ │ │ │ GPU 0 │ │ GPU 1 │ │ │ └─────────┘ └──────────┘ └──────────┘ │ │ ↓ ↓ │ │ Attention_0 Attention_1 │ │ ↓ ↓ │ │ 输出投影: 行切分 ──→ AllReduce ──→ 完整输出 │ │ │ ├──────────────────────────────────────────────────────────┤ │ MLP 层 │ │ │ │ Gate + Up 投影: 列切分（不需要 AllReduce） │ │ ┌─────────┐ ┌──────────┐ ┌──────────┐ │ │ │ X │ ──→ │ Gate0+Up0│ │ Gate1+Up1│ │ │ │ │ │ GPU 0 │ │ GPU 1 │ │ │ └─────────┘ └──────────┘ └──────────┘ │ │ ↓ ↓ │ │ Down 投影: 行切分 ──→ AllReduce ──→ 完整输出 │ │ │ └──────────────────────────────────────────────────────────┘ 每层需要 2 次 AllReduce (Attention 输出 + MLP 输出) 80 层模型 = 160 次 AllReduce !!!

三、TP 的通信瓶颈

核心洞察：TP 的最大限制是通信带宽——每层需要 2 次 AllReduce，80 层模型 = 160 次 AllReduce。这要求 GPU 间有极高带宽互联（NVLink），跨机器做 TP 效率极低。

量化分析：TP 的通信量计算：

每次 AllReduce 数据量 = batch_size × seq_len × hidden_dim × sizeof(dtype) 总通信量 = 层数 × 2 × 每次 AllReduce 数据量

以 Llama-70B 为例（hidden_dim=8192, seq_len=4096, batch=4, TP=4）：每次 AllReduce ≈ 4×4096×8192×2 = 256MB，80 层 × 2 次 × 256MB = 40GB/请求。不同互联方式的耗时：NVLink 900GB/s ≈ 0.04s，PCIe 64GB/s ≈ 0.6s，100GbE 12GB/s ≈ 3.3s。

⚠️ TP 对通信带宽要求极高！ 每层 2 次 AllReduce，每次 AllReduce 的数据量 = batch_size × seq_len × hidden_dim × 2 bytes 以 Llama-70B 为例（hidden_dim=8192, TP=4）: 每次 AllReduce 数据量 ≈ 2 × 4096 × 8192 × 2 bytes ≈ 128 MB 80 层 × 2 次 = 160 次 AllReduce 总通信量 ≈ 20 GB / 请求 不同互联方式的带宽: NVLink (H100): 900 GB/s → 160 次 AllReduce ≈ 0.02 秒 ✅ PCIe Gen5: 64 GB/s → 160 次 AllReduce ≈ 0.3 秒 ⚠️ 网络 (100GbE): 12 GB/s → 160 次 AllReduce ≈ 1.7 秒 ❌ 结论: TP 必须用 NVLink，跨机器做 TP 效率极低！

四、TP 的特点总结

核心洞察：TP 的本质是"层内并行"——将同一层的权重矩阵切分到多张 GPU，通过 AllReduce 合并结果。显存节省线性（TP=N → 1/N），延迟降低接近线性，但通信开销随层数线性增长。
